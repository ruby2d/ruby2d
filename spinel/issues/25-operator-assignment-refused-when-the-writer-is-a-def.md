# [Compile] `obj.attr += value` is refused when the writer is a `def` rather than an `attr_writer`

Filed as [#3809](https://github.com/matz/spinel/issues/3809). Found while porting [Ruby 2D](https://github.com/ruby2d/ruby2d) to Spinel.

## Description

An operator assignment to an attribute — `obj.x += 1`, `-=`, and the rest — is refused at compile time when the attribute's writer is a hand-written `def x=(v)`. The same class works if the writer is generated by `attr_writer` or `attr_accessor`, and the longhand `obj.x = obj.x + 1` works in every case.

Writers are written by hand whenever setting a value has to do more than store it — validation, a computed field, invalidating a cache. Those are the classes that cannot use `+=`.

## Reproduction

```ruby
class Rect
  attr_reader :x
  def initialize
    @x = 0
  end

  def x=(v)
    @x = v
  end
end

r = Rect.new
r.x += 1
puts r.x
```

**Ruby 4.0.6:**
```
1
```

**Spinel (83d1315d):**
```
spinel: s1.rb:12: unsupported call operator write (unsupported receiver/attr): node 21 (CallOperatorWriteNode)
```

## Additional Findings

| Variant | Result |
|---|---|
| `attr_reader :x` + `def x=(v)` | **refused** |
| `def x` + `def x=(v)` | **refused** |
| `-=` instead of `+=` | **refused** |
| the writer inherited from a parent class, or from an included module | **refused** |
| `attr_accessor :x` | compiles, prints `1` |
| `attr_reader :x` + `attr_writer :x` | compiles, prints `1` |
| longhand — `r.x = r.x + 1` | compiles, prints `1` |

The last three rows bound it: reading and writing the attribute both work, and the operator itself works. Only the fused operator-write form fails to resolve a writer that is a `def`. Inheritance is not involved — one class with both members is enough.

Rewriting each site longhand is a mechanical fix, which is what makes this cheap to work around and easy to miss: nothing warns, and the diagnostic names a node type rather than the attribute.

## Environment

- Spinel commit: `83d1315d`
